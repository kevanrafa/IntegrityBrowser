Click-throughs

What counts as suspicious?

The engine looks for elements that are nearly or fully transparent, positioned above page content, large enough to cover a meaningful part of the viewport, accepting pointer events, and empty of visible content. It ignores open dialogs, visible modals, small badges and elements explicitly marked as legitimate.

Click-through happens at gesture time: the blocking chain is temporarily disabled, the browser delivers the click to the element underneath, and the layer is restored shortly after. High-confidence static click-jackers can be neutralized for the lifetime of the page.

Browser security prevents a script from forging a trusted click. The engine first tries to let the real hardware gesture reach the underlay; a synthetic fallback is used when the browser has already fixed the click target.

Filter lists

Loading filter lists…

Add a remote list

Host-rule syntax: hosts files and ||host^ rules. Path/option rules are counted and skipped.

The list is cached in the Integrity Browser config directory and loaded offline on later starts. Lists larger than 8 MiB are rejected.

Built-in lists are compiled into the binary and can be toggled but not deleted. Remote and custom lists are stored locally. Filtering is host-based: a rule such as ||example.com^$image is skipped because blocking the whole host would over-block.

Integrity Browser 0.1.0

A functional MVP built with Rust, wry, tao and WebKitGTK/WebView2. The browser chrome is HTML/CSS/JS; the page renderer is the platform webview; filtering and state live in Rust.

The Linux build uses two GTK container rows instead of Tauri's multiwebview runtime, which places child webviews in a shared box and breaks fixed-height chrome layout. See docs/architecture.md in the source tree.

Privacy model

No telemetry, no accounts, no cloud sync. Settings and cached filter lists live in the platform config directory. The filtering proxy binds only to 127.0.0.1 on an ephemeral port. Local destinations are never blocked. HTTPS is not intercepted.

Known limitations

Tabs share one content webview, so switching tabs reloads the page. Cross-origin iframe content cannot be inspected for overlays. Page scripts can see the engine and may try to evade heuristics. Synthetic fallback clicks are not isTrusted. HTTPS filtering is hostname-only.

Test it

Run cargo test --workspace for the Rust logic, then open the Integrity self-test page for overlay scenarios. The self-test page also runs standalone in any modern browser.
